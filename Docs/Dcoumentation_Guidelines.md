## Report Structure

### Front Matter

- **Title** *(separate page)*
- **Acknowledgements** *(separate page)*
  - Mention any help obtained from any source (family, friends, supervisor, college, etc.)
- **Table of Contents** *(separate page)*
  - Generated automatically via MS Word after the report is complete
- **List of Tables** *(separate page — if applicable)*
  - Example: `Table 1: table title ……… page #`
- **List of Figures** *(separate page — if applicable)*
  - Example: `Figure 1: figure name ……… page #`

---

### Abstract

Write once the report is complete. A brief statement covering the most important points — objectives, purpose, and what the project does. **Plain text only — no images or figures.**

---

## Chapter 1: Introduction

### 1.1 Overview
A general summary of the report. Gives the whole picture of the project.

### 1.2 Objectives
The specific activities the project undergoes to meet its purpose. Must be:
- Specific
- Measurable
- Achievable
- Realistic
- Time-specific

### 1.3 Purpose
The target or output of the project — what the project aspires to achieve.

### 1.4 Scope
The range of work involved to finish the project (e.g., planning, designing, coding, testing, documentation).

### 1.5 General Constraints
Things that hindered the project from being finished on time (e.g., time constraints, unclear scope, difficulty accessing raw data).

---

## Chapter 2: Project Planning and Analysis

### 2.1 Project Planning
- **2.1.1** Feasibility Study
- **2.1.2** Estimated Cost
- **2.1.3** Gantt Chart

### 2.2 Analysis and Limitation of Existing System
Mention the main limitations of the current system and what makes it operate slowly or ineffectively.

### 2.3 Need for the New System
With evidence, support why migration from the old system is necessary. What weaknesses of the old system justify developing a new one?

### 2.4 Analysis of the New System
- **2.4.1** User Requirements
- **2.4.2** System Requirements
- **2.4.3** Domain Requirements
- **2.4.4** Functional Requirements
- **2.4.5** Non-Functional Requirements

### 2.5 Advantages of the New System
List and explain the advantages of the new system.

### 2.6 Risk and Risk Management

---

## Chapter 3: Software Design

- **3.1** Design of Database — ERD or Class Diagram
- **3.2** Use Case Diagram
- **3.3** Sequence Diagram
- **3.4** Activity Diagram

---

## Chapter 4: Implementation

### 4.1 Software Architecture
- Describe software on both client and server side
- Show communication between client and server diagrammatically
- Briefly explain the technology used for client/server communication
- Explain object-relational mappings that facilitate data transfer between client and server

### 4.2 Pseudocode, Flowchart, or Workflow
Describe the communication steps between client and server.

---

## Chapter 5: Testing

- **5.1** Unit Testing
- **5.2** Integration Testing
- **5.3** Additional Testing

---

## Chapter 6: Results and Discussion

### 6.1 Results

#### 6.1.1 Expected Results
What the project was supposed to do — the theoretical result assuming 100% functionality.

#### 6.1.2 Actual Results
The actual results achieved from the project.

### 6.2 Discussion
Differences between expected and actual results, and why actual results may have fallen short of expected ones.

---

## Chapter 7: Conclusion

Two paragraphs:
1. **Summary** — includes a summary of the report and achievements
2. **Recommendation** — how to enhance the project if given the right resources

---

## Chapter 8: Future Work

Mention future work involved to improve the project.

---

## Back Matter

### Bibliography
Lists all materials consulted while writing the report (not necessarily cited directly in the text). Include:
- Books
- Magazines and periodicals
- Websites
- Scientific papers

### Appendix
Use for long or supplementary material that would otherwise clutter the main report body:
- Long code listings
- Calculations
- Pictures, maps, graphs, illustrations, photographs
- Survey questionnaires
- Personal reflections or interviews
- Any other additional information
