# Documentations

This folder collects project documentation that is not tied to a single package.
Use it for architecture notes, setup guides, runbooks, and decision records that
apply across the repository.

## Why we use it
- Keep shared knowledge in one place.
- Avoid scattering long-form docs across multiple packages.
- Make onboarding and maintenance easier.

## How to use it
- Create a folder per service (e.g. `frontend`, `backend`).
- Inside each service folder, create a folder per topic.
- Each topic folder should include a `README.md` that explains the topic and how to use it.
- Keep docs short, focused, and updated with code changes.
- Link to these docs from package-level READMEs when relevant.
